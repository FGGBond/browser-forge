# Browser Forge 三栏分析指导与录制仓库精简设计

**日期：** 2026-08-10  
**状态：** 待用户书面确认  
**范围：** 录制详情分析工作区、三步 Markdown 指导、外部 Agent 提示词、录制仓库与全局英文眉题精简

## 1. 背景与目标

当前录制详情将分析区实现为覆盖主内容的模态 Sheet。打开后视频被遮罩、背景不可操作，用户无法边播放录制视频边撰写说明，这与分析区的核心用途冲突。当前单个大文本框还混合了动作、能力、输入输出和成功标准，用户需要理解整份模板后才能开始填写。

本次设计实现以下目标：

1. 桌面端详情页采用真正的三栏工作区：左侧录制导航、中间视频、右侧分析指导。右栏不覆盖视频，不禁用视频操作。
2. 将分析说明拆成三个聚焦问题，用户一次填写一个问题，可以前后返回修改，并在最后统一检查。
3. 每个问题使用本地离线的 EasyMDE Markdown 源码编辑器，支持必要 Markdown 能力与预览，不依赖 CDN。
4. 当前未配置 Agent/API key 时，在右栏顶部清楚说明状态；同时明确分析将使用 `browser-forge` skill。
5. 自动保存但隐藏正常保存状态，只在保存失败时显示可恢复错误。
6. 删除界面中的英文眉题和低价值录制状态信息，让视频、标题和主要操作成为视觉中心。
7. 保持现有 `prompt.md`、导出和外部 Agent 复制流程兼容，为后续 Reasonix 接入留下稳定接口。

## 2. 不在本阶段实现

- 不在本阶段运行内置 Agent、调用 DeepSeek API 或保存 API key。
- 不在本阶段改变录制视频、timeline、HAR、导出目录或回收站的数据格式。
- 不在本阶段引入聊天消息历史；右栏首先是生成 skill 前的结构化需求采集器。
- Reasonix 的接入架构在本 UI 阶段验证完成后单独调研和设计。

## 3. 详情页信息架构

### 3.1 桌面三栏

应用最外层继续使用现有工作区导航作为第一栏。详情页主区域由以下两栏组成：

- **中栏：录制视频工作区**
  - 录制名称、创建时间、站点信息。
  - 视频播放器。
  - “去分析”“导出”“移入回收站”操作。
- **右栏：分析指导区**
  - 固定在详情工作区右侧，宽度建议为 `360–420px`，默认目标宽度 `390px`。
  - 与中栏共同参与 CSS Grid 布局，不使用 `position: fixed`、遮罩、`aria-modal` 或背景 `inert`。
  - 视频在右栏打开时仍然可以播放、暂停、拖动、切换倍速和全屏。

打开右栏时，中栏获得剩余宽度并重新排版。布局切换本身不做大幅滑动或遮罩动画；右栏内容使用短距离 `translateX(10px)` 与 opacity 的 180ms 进入反馈。关闭使用 140ms。`prefers-reduced-motion` 下仅淡入淡出。

### 3.2 窄窗口

- 当详情工作区无法同时容纳可用的视频和 `360px` 右栏时，右栏改为视频下方的普通内容区，而不是覆盖视频。
- 移动/窄窗口仍保持“先看视频，再填写分析”的自然阅读顺序。
- 不出现横向页面滚动。

### 3.3 右栏顶部

删除以下内容：

- `Analysis session`
- `分析会话`
- 独立的大标题栏

右栏顶部只保留一个紧凑状态卡和关闭按钮：

- 标题：`尚未配置 Agent`
- 说明：`完成下面的说明后，可以复制给外部 Agent；接入 Agent 后也可直接在这里开始分析。`
- skill 标识：带图标的 `browser-forge skill`
- 关闭按钮位于右上角，aria-label 为 `关闭分析栏`

当未来 Agent 已配置时，同一区域替换为 provider/model 状态和“开始分析”操作，不改变三步表单的数据结构。

## 4. 三步需求引导

### 4.1 共同结构

右栏主体一次只展示一个问题：

- 顶部显示 `1 / 3`、`2 / 3` 或 `3 / 3` 和三段式进度指示。
- 问题标题、简短解释、一个 Markdown 编辑器。
- 底部固定操作区：
  - 第一步：`下一步`
  - 第二步：`上一步`、`下一步`
  - 第三步：`上一步`、`检查并完成`
- 用户可以点击已完成的进度步骤返回修改，但不能跳过尚未到达的步骤。
- “下一步”不强制内容非空，避免阻断探索；空内容会在最终检查页标记为“待补充”。

### 4.2 问题一：动作与意图

**标题：** `这次录制中，你完成了什么？`

**解释：** `说明你的操作目标、关键步骤，以及为什么这样操作。无需逐帧复述，只保留生成能力所需的行为。`

**占位示例：**

```markdown
我进入订单后台，使用订单号搜索目标订单，打开详情页并读取物流状态。

关键步骤：
- 输入订单号并搜索
- 打开唯一匹配的订单
- 读取承运商、运单号和最新物流节点
```

### 4.3 问题二：希望提取的能力

**标题：** `希望把这段操作变成什么能力？`

**解释：** `描述未来 Agent 会收到什么输入、要完成什么浏览器任务，以及应返回或改变什么。`

**占位示例：**

```markdown
生成一个订单物流查询 skill。

用户提供订单号后，Agent 应自动完成查询，并返回：
- 承运商
- 运单号
- 最新物流状态
- 最近更新时间
```

### 4.4 问题三：验收标准

**标题：** `怎样证明这个 skill 可以交付？`

**解释：** `给出一条可执行的验收任务、测试输入，以及完成后应看到的明确结果。`

**占位示例：**

```markdown
使用测试订单号 `JD123456789` 运行 skill。

验收通过条件：
- 找到对应订单且不会打开其他订单
- 返回承运商和运单号
- 返回的最新物流节点与订单详情页一致
- 查询过程不会修改订单数据
```

### 4.5 最终检查页

完成第三步后进入同一右栏内的检查页：

- 展示三个答案的紧凑 Markdown 预览。
- 每段右上角提供“修改”，返回对应步骤。
- 缺失答案显示 `待补充`，不显示保存状态。
- 明确显示最终分析方式：`使用 browser-forge skill 分析录制并生成可独立运行的 skill 与 CLI 工具。`
- 操作：
  - `返回修改`
  - `复制给外部 Agent`
- 内置 Agent 未配置时不展示伪造的“开始分析”按钮。

## 5. Markdown 编辑器

### 5.1 选型

采用 EasyMDE，原因：

- 可直接增强现有 textarea，适合当前 Vanilla JavaScript UI。
- Markdown 源文本始终可获取，能继续保存到 `prompt.md`。
- 自带预览、快捷键与基础编辑能力。
- 比 Toast UI Editor 更轻、更贴合狭窄侧栏；比从 CodeMirror 6 自建编辑器更快形成稳定体验。

### 5.2 离线集成

- 通过 npm 固定 EasyMDE 版本。
- App 只加载本地打包资源，不使用 CDN、远程字体或运行时下载。
- 显式保留 EasyMDE 的开源许可证信息。
- 初始化失败时退化为原生 textarea，用户仍可编辑和保存，不阻断详情页。

### 5.3 工具栏

右栏宽度有限，只保留：

- 加粗
- 斜体
- 无序列表
- 有序列表
- 链接
- 预览

不提供全屏、分栏预览、图片上传、表格、引用帮助弹窗或远程图片上传。工具栏必须使用本地 SVG/文字，不下载 Font Awesome。

## 6. `prompt.md` 数据结构与兼容性

继续使用一个 `prompt.md`，不新增用户可见的材料文件。新格式是可读、可复制的结构化 Markdown：

```markdown
## 本次录制中的动作与意图

<第一步答案>

## 希望提取的 skill 能力

<第二步答案>

## Skill 验收标准

<第三步答案>
```

实现提供纯函数：

- `parseGuidanceMarkdown(text)` → `{ actions, capability, acceptance, legacy }`
- `serializeGuidanceMarkdown(fields)` → 上述稳定 Markdown

兼容规则：

- 空 prompt：三个字段为空，编辑器只显示占位示例，不把占位内容自动保存。
- 新结构 prompt：按三个固定二级标题解析。
- 旧自由文本 prompt：全文放入第一步，`legacy: true`；第二、三步为空。第一次编辑保存后转为新结构，原文不会丢失。
- 保存仍使用现有 256KB 总大小限制。

## 7. 自动保存与错误

- 任一编辑器内容改变后延迟 500ms 保存完整结构化 Markdown。
- 切换步骤、关闭分析栏、离开详情、导出或移入回收站前执行 flush。
- 正常情况下不显示：`说明尚未保存`、`未保存`、`正在保存`、`已保存`。
- 保存失败时在当前问题上方显示可关闭的错误条：`保存失败，内容仍保留在编辑器中。`
- 失败后不丢弃用户输入；再次输入或点击 `重试保存` 可恢复。

## 8. 外部 Agent 提示词

`buildExternalAgentPrompt()` 保持录制路径只在复制/调用时动态加入，不写入 `prompt.md`。最终提示词必须包含：

1. 明确指令：使用已安装的 `browser-forge` skill。
2. 录制物料绝对路径。
3. 三段结构化用户说明：动作与意图、目标能力、验收标准。
4. 按 `videoOffsetMs` 使用内置零依赖工具抽取视频帧的要求。
5. 产物要求：可独立运行的 skill、清晰输入输出契约和 CLI 工具。
6. 验证要求：执行用户给出的验收任务，并说明结果是否满足标准。

## 9. 录制仓库与全局文案精简

### 9.1 删除所有同类英文眉题

从用户可见 UI 删除：

- `Recording workspace`
- `Recording repository`
- `Analysis session`
- `Agent guidance`
- `Chrome window`
- `Recycle bin`

不以其他英文大写眉题替代。产品名称 `Browser Forge`、skill 名称 `browser-forge` 和必要技术名词不属于该删除范围。

### 9.2 录制仓库卡片

卡片继续以视频为主。视频下方只保留：

- 录制标题
- 创建日期时间
- `去分析` 按钮

删除：

- 录制时长，例如 `00:13`
- `分析说明待补充` / `已有分析说明`
- `视频可用` / `视频部分可用` / 状态圆点
- 域名副标题或“未知网站”

视频不可播放时，播放器区域仍需要一个必要的错误/不可用空状态；这属于故障反馈，不属于卡片元信息。

### 9.3 其他页面

- 新录制、正在录制和回收站中的英文眉题一并删除。
- 保留中文页面标题、必要状态和错误信息。
- 侧栏品牌区只显示 `Browser Forge`，不显示 `Recording workspace`。

## 10. 可访问性与键盘行为

- 三栏右侧不是 dialog，不设置 `aria-modal`，不让视频和侧栏 inert。
- `去分析` 使用 `aria-expanded` 与右栏 id 建立关联。
- 打开右栏后焦点进入当前问题标题或编辑器；关闭后回到 `去分析`。
- EasyMDE 工具栏按钮具有中文 aria-label 和 tooltip。
- 步骤指示使用有序列表语义，当前步骤使用 `aria-current="step"`。
- 保存失败使用 `role="alert"`；正常自动保存不使用 live region。
- 所有功能支持键盘操作，颜色不是唯一状态表达。

## 11. 测试与验收

### 自动化测试

- 详情页在桌面宽度下形成中栏 + 右栏布局，不存在 fixed pane/backdrop/modal/inert。
- 打开分析栏后视频播放器保持可交互。
- 三步可前进、后退和返回修改，字段不会丢失。
- EasyMDE 加载成功；资源不可用时 textarea fallback 可编辑。
- 旧 prompt 能无损进入第一步并在保存后迁移。
- 自动保存、并发编辑、保存失败和 beforeNavigate flush 保持正确。
- 外部提示词包含 `browser-forge`、三个答案、录制路径和验收执行要求。
- 用户可见源码与浏览器测试中不存在被删除的英文眉题和卡片冗余信息。
- 520px、640px、900px、1280px 宽度无横向溢出。

### 视觉验收

- 1280px 及以上：左侧录制导航、视频、分析指导三栏同时可见。
- 右栏打开时视频不被遮挡，仍能播放和拖动进度。
- 右栏视觉接近 Codex 侧边聊天：边界清晰、内容密度克制、底部操作稳定、无大标题浪费空间。
- 深色与浅色模式均有清晰层级。
- 三个问题的标题、解释和示例能让首次使用者无需说明书即可完成。
