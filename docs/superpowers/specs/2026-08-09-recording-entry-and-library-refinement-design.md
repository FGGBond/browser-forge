# 新录制与录制仓库界面精简设计

**日期：** 2026-08-09
**状态：** 已由用户截图与文字要求确认

## 目标

1. 新录制页不再像权限说明书，只保留目标输入、发送目标和开始录制两个核心动作。
2. 权限、等待和错误状态脱离表单，作为输入框上方可关闭的轻量层叠通知出现。
3. 点击开始录制时自动执行权限请求；正常状态不展示权限说明、恢复按钮组或高级设置。
4. 录制仓库以视频为绝对主内容，其他信息压缩进视频下方的窄信息栏。

## 新录制页

- 保留居中的问题标题“有什么想要完成的浏览器操作？”，移除图标、英文眉题、长说明、录制范围说明和默认展开入口。
- Composer 参考 Codex：大面积无边框文本输入，底部工具栏只包含：
  - `开始录制`：无论目标是否为空都可触发；若权限缺失，先自动请求权限，再继续录制。
  - 圆形发送按钮：提交当前目标；若有文字，显示短暂的“目标已记下”通知，不伪造 Agent 回复。
- Chrome 路径继续自动探测，默认不展示。只有探测失败时才通过上方通知提供最小恢复输入。
- 通知位于 composer 上方，最多形成三层轻微错位的堆叠；支持关闭。通知仅陈述当前状态，并按需提供一个上下文动作，例如“重新启动”。
- 首次权限失败时自动打开系统设置；窗口重新获得焦点后自动复查权限，不要求用户主动点击“再次检查”。
- 不自动重置或删除系统权限；这类操作仍必须由用户明确触发或由开发协助处理。

## 录制仓库

- 每段录制继续独占一行，但卡片内部改为上下结构。
- 视频区域占据卡片完整宽度，保持 16:9，取消当前左右分栏造成的小预览。
- 视频下方只保留一条紧凑信息栏：标题、网站、录制时间、时长、分析说明状态、视频状态与“去分析”。
- 元信息不再使用三个占空间的方块，改成单行短文本；窄屏下允许自然换行，但视频仍优先。
- 播放器继续使用既有私有无声控件，不加入原生 controls、音量、下载或画中画。

## 可访问性与响应式

- 两个核心动作均有清晰 accessible name、键盘焦点和 disabled/busy 状态。
- 通知使用 `role=status` 或 `role=alert`，关闭按钮具备可访问名称。
- 520px、640px、900px 与桌面宽度下，composer 不横向溢出；仓库信息栏可换行而视频保持完整。
- 遵循 reduced-motion；通知堆叠只使用短距离 transform/opacity，不使用弹跳。
