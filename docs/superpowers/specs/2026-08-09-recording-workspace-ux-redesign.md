# Browser Forge 录制工作台 UI/UX 重构设计

日期：2026-08-09  
状态：已实现并通过回归验证（采用方案 A：本地优先、Agent-ready）

## 1. 背景与目标

Browser Forge 已具备完整的 Chrome 窗口录制、录制库、回收站、视频与提示词物料能力。本次重构不改变“本地录制优先”的产品边界，而是将现有以卡片详情为中心的管理界面升级为一个面向未来分析 Agent 的录制工作台。

本设计必须同时满足：

1. macOS 深色和浅色主题中所有页面均具备稳定、自然、可读的表现；
2. 左侧栏将每段录制作为长期工作对象，而不是在右侧临时卡片中选择；
3. “新录制”采用 Codex 新会话式目标输入体验；
4. 录制仓库提供单行宽幅视频浏览、搜索和进入分析的入口；
5. poster 表示用户首次成功加载的外部网页，而不是 Browser Forge 引导页；
6. 使用完全自定义、无音频、无画中画、无下载入口的视频播放器；
7. 录制分析页预留右侧多会话 Agent 容器，左右侧栏均可折叠；
8. 用户界面不再暴露“录制物料”和“关键事件”等内部实现概念，但保留网站、时间、时长等有用元信息和外部 Agent 提示词能力。

## 2. 产品原则

### 2.1 所见即所得

用户首先理解视频，而不是 HAR、DOM、事件或截图等底层物料。内部材料仍完整保存并供 Agent 使用，但普通 UI 不主动展示。

### 2.2 不伪造 Agent 能力

当前没有配置分析 Agent 时：

- “新录制”输入的目标文本保存为该录制的初始说明；
- 分析侧栏明确显示 Agent 尚未配置；
- 用户仍可编辑、预览和复制完整提示词给外部 Agent；
- 不生成规则式假回复，也不制造“正在分析”的错觉。

未来接入 Agent 后，输入区和分析侧栏直接升级为多会话对话，不重做信息架构。

### 2.3 录制是工作对象

每段录制是类似 Codex 项目的长期对象。录制可以产生多个分析会话；本期只呈现录制一级条目，但布局和状态命名不得阻碍未来加入子会话。

### 2.4 安全边界不可因 UI 重构弱化

- 录制视频仍只录制专用 Chrome 窗口；
- 媒体 URL 不在可见 UI 中展示；
- 播放器不提供下载、画中画、音量或浏览器原生菜单；
- 导出仍是唯一显式把物料复制到用户目录的方式。

## 3. 整体信息架构

```text
┌──────────────────────┬──────────────────────────────────┬──────────────────────┐
│ 左侧录制导航         │ 主工作区                         │ 分析会话侧栏         │
│                      │                                  │                      │
│ [新录制]             │ 新录制 / 录制仓库 / 分析工作区  │ Agent 会话 / 外部说明│
│                      │                                  │                      │
│ 录制仓库             │                                  │ 可折叠               │
│   录制 A              │                                  │                      │
│   录制 B              │                                  │                      │
│   录制 C              │                                  │                      │
│                      │                                  │                      │
│ 回收站                │                                  │                      │
│ 可折叠                │                                  │                      │
└──────────────────────┴──────────────────────────────────┴──────────────────────┘
```

### 3.1 左侧栏

顺序固定：

1. Brand；
2. 顶部主操作“新录制”；
3. “录制仓库”入口；
4. 当前 active 录制列表；
5. “回收站”；
6. 本地保存状态；
7. 折叠按钮。

行为：

- 点击“录制仓库”进入总览；
- 点击具体录制进入该录制的分析工作区；
- 当前选中条目使用低对比度填充和清晰文字，不使用高饱和整块蓝色；
- 标题单行截断，悬停显示完整名称；
- 每段录制显示站点 favicon/首字母图形和可选的未完成提示状态；
- 左侧栏折叠后保留品牌图标、新录制、仓库、回收站及当前录制图标；
- 折叠状态保存到 `localStorage`，仅属于 UI 偏好。

### 3.2 路由

保持当前无框架路由方式，但语义调整为：

- `new-recording`：新录制目标页；
- `library`：录制仓库总览；
- `detail`：录制分析工作区；
- `recording`：进行中的录制状态页；
- `trash`：回收站。

导航时左栏录制列表应保持稳定，仅在创建、重命名、移入回收站或恢复后刷新。

## 4. 深浅主题系统

### 4.1 主题来源

首期跟随系统：

```css
:root { color-scheme: light; }
@media (prefers-color-scheme: dark) {
  :root { color-scheme: dark; }
}
```

不得继续使用“浅色 token + `color-scheme: light dark`”的混合模式。所有自定义表面、文本、边框、状态色、浮层和控件都必须来自语义 token。

### 4.2 核心语义 token

至少包含：

- `--canvas`：主工作区背景；
- `--sidebar`：左侧栏背景；
- `--panel`、`--panel-raised`、`--panel-muted`；
- `--text-primary`、`--text-secondary`、`--text-tertiary`；
- `--border`、`--border-strong`；
- `--selection`、`--selection-hover`；
- `--accent`、`--accent-hover`、`--accent-contrast`；
- `--danger`、`--success`、`--warning` 及对应柔和背景；
- `--scrim`、`--shadow-*`、`--focus-ring`；
- 播放器专用的黑色表面和高对比度控件 token。

### 4.3 主题质量门槛

- 正文与背景至少满足 WCAG AA 对比度；
- placeholder、disabled 和 tertiary 文本仍可辨认，不以极低 opacity 代替颜色设计；
- 浅色卡片不得在深色主题残留；
- 原生 `input`、`textarea`、`select`、`dialog`、`range` 需要显式样式；
- hover 仅在 `hover:hover` 下启用；
- focus-visible 具有统一可见焦点环；
- `prefers-reduced-motion` 下移除非必要运动。

## 5. 新录制页面

### 5.1 页面结构

采用 Codex 新会话式居中工作区：

- 页面中心图标；
- 主标题：“有什么想要完成的浏览器操作？”；
- 一句话说明：“先描述目标，或直接开始录制。录制只包含 Browser Forge 打开的 Chrome 窗口。”；
- 目标输入 composer；
- composer 底部状态与开始按钮；
- 可折叠权限/浏览器设置；
- 权限异常时在 composer 下方出现就地恢复卡片，不跳回旧的表单式大卡片。

### 5.2 当前无 Agent 时的行为

- textarea 可为空；
- 用户输入内容保存在内存中，录制成功创建 recordingId 后立即写入该录制 prompt；
- 如果保存 prompt 失败，不应让录制失败，但必须在录制完成页提示用户重新保存；
- 状态文案：“分析 Agent 尚未配置，目标会保存为录制说明”；
- 主按钮：“开始录制”；
- 不出现假对话消息。

### 5.3 录制中页面

录制进行时主工作区只显示：

- 录制状态与计时；
- 当前网站/标签页简要信息；
- “停止并保存”；
- 最小化的隐私边界说明。

不再展示事件数量、网络请求、Console、截图或实时事件流。它们继续在后台采集。

## 6. 录制仓库

### 6.1 总览布局

每段录制独占一行，不使用紧凑卡片网格。行结构：

```text
┌────────────宽幅视频/Poster────────────┬────────────信息────────────┬────操作────┐
│ 16:9，可直接播放，自定义控件          │ 名称                        │ 去分析      │
│                                      │ 网站 · 创建时间 · 时长       │ 更多/回收站 │
│                                      │ 提示词状态                   │            │
└──────────────────────────────────────┴────────────────────────────┴────────────┘
```

- 视频区域在桌面宽度下不低于 360px；
- 行内播放不得影响点击“去分析”；
- 点击标题、信息区域或“去分析”进入分析页；
- 删除/回收站操作必须与行跳转隔离；
- 无视频时使用清晰的状态占位，不展示内部错误细节；
- 列表支持空状态、加载骨架和错误重试。

### 6.2 搜索

本期搜索字段包括：

- 录制名称；
- 首个外部网站 host；
- 已采集 timeline 中的外部 URL host/path 文本；
- 用户 prompt 文本（可选，若不会造成明显性能问题）。

为未来网页正文搜索预留 `searchText`/索引层，但本期不把整个 DOM 内容直接塞入 library.json。

搜索在服务端完成，避免前端只搜索当前分页/已加载数据。输入使用 180–250ms debounce。

## 7. Poster 生成

### 7.1 目标时刻

poster 必须对应“用户首次成功加载的外部网页”。定义：

- 忽略 `localhost`、`127.0.0.1`、`::1` 和 Browser Forge 引导页；
- 找到 timeline 中首个外部 `navigation` 事件；
- 使用该事件的 `videoOffsetMs` 加稳定延迟（建议 500–900ms）作为 poster 提取时间；
- 提取时间限制在视频有效区间内；
- 若不存在有效外部导航，则回退到首个非引导页截图对应时间；
- 仍不存在时才回退到视频 20%/最多 1 秒策略。

### 7.2 可靠性

- poster 生成失败不使录制失败；
- metadata 只有在文件实际生成后才声明 poster；
- poster 重新生成逻辑保持幂等；
- 测试覆盖外部导航、无外部导航、partial 视频和极短视频。

## 8. 自定义视频播放器

### 8.1 原生媒体元素策略

底层继续使用 `<video>` 解码，但：

```html
<video
  playsinline
  preload="metadata"
  disablepictureinpicture
  disableremoteplayback
  controlslist="nodownload noplaybackrate noremoteplayback"
></video>
```

- 不设置 `controls`；
- `muted = true`，且不提供声音控制；
- 拦截 `contextmenu`，不提供原生媒体菜单；
- 不调用 Picture-in-Picture API；
- UI 不渲染媒体 URL，因此不显示 `127.0.0.1:<port>`；
- 端口仍是 App 内部本地 HTTP 实现细节，不在用户可见控件中暴露。

### 8.2 控件

播放器控件包括：

- 播放/暂停；
- 后退 5 秒；
- 前进 5 秒；
- 当前时间 / 总时长；
- 可拖动进度条；
- 倍速菜单：`0.5× / 0.75× / 1× / 1.25× / 1.5× / 2×`；
- 全屏；
- 键盘：Space、←、→、J、K、L、F；
- 加载、错误、partial 视频状态；
- 控件在播放时延迟淡出，鼠标移动、键盘焦点或暂停时显示；
- 无音量、下载、画中画、投屏按钮。

### 8.3 复用

同一个 `createVideoPlayer` 组件同时用于：

- 仓库行内预览（compact 模式）；
- 分析工作区（full 模式）。

compact 模式可省略倍速文字但必须保留播放、进度和进入全屏的能力。

## 9. 录制分析工作区

### 9.1 主区域

主区域只展示：

- 可编辑录制标题；
- 网站、创建时间、时长、视频状态等必要元信息；
- 大幅自定义播放器；
- 导出、移入回收站；
- 打开/折叠分析侧栏的按钮。

不展示：

- “录制物料”标题或底层物料清单；
- “关键事件”列表；
- HAR、DOM、Console、截图数量。

### 9.2 右侧分析栏

宽度建议 320–400px，可折叠。结构：

- 顶栏：“分析会话”与关闭按钮；
- Agent 未配置状态；
- “告诉 Agent 你想实现什么”编辑器；
- 自动保存状态；
- “复制给外部 Agent”；
- “预览完整提示词”；
- 未来会话列表/消息区域占位在数据结构中，但本期不展示空的伪会话列表。

右侧栏打开时主视频自适应缩小，不覆盖内容。窗口过窄时右栏变为 modal sheet；左右栏均不能使播放器小于可用阈值。

### 9.3 多会话预留

本期不创建分析会话实体，但组件和命名使用：

- `analysis-pane`；
- `analysis-session-header`；
- `recordingId` 作为父级上下文；
- prompt 视为默认的“未接入 Agent”草稿，而不是未来唯一会话数据。

## 10. 回收站

回收站继续独立入口，但适配新主题和左侧栏。列表使用简洁单列，不进入分析模式。恢复后回到对应录制分析页。永久删除保留明确确认和不可撤销说明。

## 11. 状态与交互细节

- 导航、折叠、播放器模式变化使用 160–220ms ease-out，避免大面积弹跳；
- 列表加载可以轻微 stagger，但不能阻塞操作；
- 所有图标按钮有 `aria-label` 和 tooltip；
- 所有媒体控制具备键盘操作；
- 标题重命名、prompt 保存、回收站移动均有明确成功/失败反馈；
- 新录制开始后禁用导航，停止或失败后恢复；
- 不再在主导航和页面标题区重复放置两个“新建录制”按钮。

## 12. 数据与 API 变化

预计新增或调整：

1. `POST /api/start-recording` 接受可选 `goalText`；或在创建 recordingId 后由前端立即调用已有 prompt API。推荐由 start API 接收 `goalText`，在 staging 阶段一起持久化，避免录制意外终止导致目标丢失；
2. library 列表返回可搜索的站点摘要，并可选返回 `visitedHosts`；
3. poster generator 接受 `timeline` 或显式 `offsetMs`；
4. 不新增暴露底层材料的用户 API；
5. 媒体 Range API 保持不变。

## 13. 测试与验收

### 13.1 自动化测试

- 深浅主题 token 完整性与禁止硬编码浅色表面检查；
- 左栏录制列表、选中状态、折叠和导航；
- 新录制目标输入持久化；
- 仓库单行布局和搜索；
- 自定义播放器不含原生 `controls`，禁止 PIP/下载/声音，快进快退、倍速和全屏逻辑；
- 分析页不出现“录制物料”“关键事件”；
- 分析栏折叠与 prompt 保存/复制；
- poster offset 根据首个外部导航计算；
- 回收站、导出和重命名回归；
- 现有录制权限与 native recorder 测试继续通过。

### 13.2 视觉验收矩阵

页面：

- 新录制；
- 录制中；
- 录制仓库（有数据、空、搜索无结果）；
- 分析工作区（侧栏开/关、视频 complete/partial/failed）；
- 回收站（有数据、空、确认对话框）。

环境：

- macOS light；
- macOS dark；
- 1200×800；
- 900×700；
- reduced motion；
- 键盘-only 操作。

每个页面必须检查：文字对比度、焦点、hover、禁用、错误、长标题、长网站和空状态。

## 14. 非目标

本期不实现：

- 真正的 Agent API 调用；
- 分析会话持久化与多会话树；
- 网页全文索引；
- 音频录制和播放；
- 用户自定义主题切换器；
- Windows 原生录制后端。

这些能力的结构已预留，但不得用空按钮或假交互提前暴露。


## 15. 实施与验证记录（2026-08-09）

本规格已在 `feat/window-video-recording` 分支按独立任务点实现：

- 主题安全的工作台壳层、录制导航与折叠偏好；
- 目标优先的新录制流程，并将目标保存为分析说明草稿；
- 无原生 controls、音量、下载和画中画入口的自定义视频播放器；
- 单行宽幅视频录制仓库与跨访问站点搜索；
- 首个成功外部网页的时间线 poster 选择；
- 可折叠的录制分析工作区与未配置 Agent 的外部提示词流程；
- 单列回收站、简化录制状态页、键盘焦点、窄屏和 reduced-motion 完善。

最终验证证据：

- `git diff --check`：通过；
- `npm test`：62 个测试文件、343 项测试全部通过；
- `npm run build`：Main、Preload、Renderer 生产构建全部成功；
- Playwright 视觉巡检：light/dark、1280×800、900×700；
- Playwright 自动化覆盖：520px/640px 窄屏、键盘焦点、reduced motion、播放器、回收站、提示词自动保存与录制生命周期；
- 产品边界测试确认：可见 UI 不出现“录制物料”“关键事件”“画面物料”，不使用原生视频 controls，不提供音量、下载或画中画入口，不伪造 Agent 回复。
